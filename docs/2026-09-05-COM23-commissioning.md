# 36GP-555 单板调试记录 · 2026-09-05

## 当前结论和坐标

当前是**可运行的单板调试版本，不是全部力反馈目标已完成**。固件 `0.4.25-commissioned-36gp` 已编译、写入校验并从真实板端查询。电机为用户照片中的 24 V / 1538 rpm / 1:5.2 的 36GP-555；实测母线约 19.49 V。运行应用口 COM23，USB 序列号 `68EE8F52A79C`。同一板进入下载模式时出现 COM18，不代表第二块板。

磁编码器位于**电机后轴**。所有固件命令、PID误差和网页目标均为后轴坐标；换成圈时除以360，换成rps时速度除以360。减速箱输出的理想推算再除以5.2，例如：

| 指令（后轴） | 减速箱输出推算 |
|---|---|
| 0.52° | 0.1° |
| 5.2° | 1° |
| 52° | 10° |
| 468° | 90° |
| 93.6°/s | 0.05圈/秒 |
| 374.4°/s | 0.2圈/秒 |
| 1872°/s | 1圈/秒 |

这些输出值只是减速比换算，**未使用输出端量具或第二编码器验证齿隙、绝对角度和反向重复性**。后轴14位计数的量化间隔也不等于系统绝对精度。

## 这次修复的代码问题

1. 速度PI抗积分饱和之前没有把全部前馈纳入比较，会在仍需克服负载时冻结积分。36GP档案现根据真实电流限幅决定积分，改变Ki保留积分输出。
2. 位置环按 `Kp×目标误差 + Ki×积分 − Kd×后轴速度` 产生速度目标；保留外环限幅和加减速。36GP默认到位后持续保持，重复同一目标只续期，不重置控制状态。原775的最低2 A、脱困脉冲和禁止反向制动的规则不再套用。
3. ADC每次读取重新配置/标定，曾严重拉低循环频率；改成一次校准、快速读取及短采样突发。200 Hz位置环有独立期限，不再嵌套在500 Hz速度节拍里被取整到约167 Hz。
4. 真12位PWM（0–4095）显式使用80 MHz APB时钟，实测载波19531 Hz。中间版本使用自动40 MHz时钟配置失败，`pwm_hz=0` 的异常被实际诊断发现并修复；现在PWM未配置时拒绝唤醒和运动。
5. 当前36GP电流控制使用R/Ke前馈与两自由度PI，电流比例项不直接对设定值阶跃作放大。直接电流诊断有10 A/s参考斜率；速度环电流输出斜率80 A/s，取消旧的隐藏12 A/s限制。
6. 编码器多圈只由板端累计；校验后的原始角度增量参与反馈。角度扰动表按原始磁角查询，不受多圈清零影响。保持真实误差和采样噪声，不把网页曲线伪造为平滑线。
7. TinyUSB诊断输出使用有界非阻塞队列，串口命令需要板端ACK；STOP不等待普通命令队列。重连使用新会话序号，旧目标不自动复活。任务看门狗1秒超时后回到安全启动状态（已核验配置，但未做带电阻塞故障注入）。
8. 发现后端固定 `read(256)` 会把2–3个遥测帧凑成一批；改为读取当下可用数据。相同只读浏览器测试由约35 fps提高到56 fps，板端采样仍为100 Hz。绘图帧率受显示刷新与浏览器调度限制，未宣称已经100 fps。
9. 遥测时间戳改为64位系统微秒时钟换算毫秒，避免旧32位 `micros()/1000` 约71分钟回绕被网页误判重启。这是静态发现的隐患，尚未做跨71分钟持续运行验收。
10. 网页增加三种目标的精调量程、小角度细刻度、圈值六位小数、图内单位。量程/单位切换不发送运动，限时诊断正常结束不再冒充硬故障弹窗。真实故障仍弹窗。

| 位置 Kp / Ki / Kd | 12 / 0 / 0.15 |

| 当前存储的电气模型 | R=6.20926 Ω，Ke=0.022754 V/(rad/s) |
| 原始转角补偿 | 18阶谐波；比例1.0；总修正限幅±0.3 A |
| 默认操作时间 | 电流1秒；速度3秒；位置保持可续期，STOP结束 |

转角扰动以 `I = 加速度/(Kt/J) + 黏性项 + 库仑项 + 原始转角谐波` 做有界最小二乘，整圈留出验证，而非随机拆分相邻采样。所用校准是 [20260905-102108-COM23-837600.rotor-fit.json](../evidence/commissioning/20260905-102108-COM23-837600.rotor-fit.json)，留出圈R²约0.991、残差RMSE约0.0156 A。它已写入本板NVS，复位后读回 `scale=1.000`；**拟合度不是独立力矩或角度测量结果**。

换电机、挪磁铁、改接线后应清除并重新辨识。命令 `cascade cogging clear` 清RAM，随后 `cascade cogging save` 持久化；方向/采样极性改变或模型重置会停止运动并使旧补偿失效。不会按COM口/MAC选择“特殊参数”。

## 实测过程，不只看终点

原始记录保留了成功、失败和中间版本，不能把目录中所有文件都当成最终版本成绩。每个文件内 `MODEL fw=` 可识别真实运行版本。统计脚本按板端时间、控制模式和实际请求目标筛选数据，不把前一个目标的尾帧混进新阶跃。

### 电流

- 最终版 +100 mA：1024点高速记录约1999.86 Hz，首达90%约7.16 ms，前20 ms连续落在±10 mA内的起点约18.01 ms；记录峰值120.4 mA，末100 ms均值101.59 mA、误差RMS4.85 mA。
- 前一版同一控制律 −100 mA：约1999.89 Hz，首达90%约7.29 ms，峰值绝对值110.32 mA，末100 ms均值−99.61 mA、误差RMS3.29 mA。
- 高速记录最大采样间隔约1.46–1.50 ms，不能把平均2 kHz说成完全无抖动的硬实时。位置长测试从循环计数差得到约1.96 kHz电流更新，速度/位置约500/200 Hz；ADC、I²C和控制仍共享Arduino任务。
- 电流是INA240校准后的板端反馈，尚未用独立串联电流表/示波器验证小电流绝对准确度。PWM下电源平均输入电流不能直接当作电机绕组电流真值。

证据：[正向高速采样](../evidence/commissioning/20260905-104847-COM23-285200.jsonl)、[波形](../evidence/commissioning/20260905-104847-COM23-285200.png)、[负向高速采样](../evidence/commissioning/20260905-104418-COM23-603700.jsonl)。

各目标均持续控制约14秒，统计**完整末10秒**，并非只抽最后一帧：

| 0.4.24 / 468° | 90° | 0.06° | 0.06° |

在严格±0.1°后轴误差带内，“进入后不再超出”的时间个别段接近11–14秒，不能声称全部亚秒精确稳定；末段细小磁阻/量化变化仍保留在曲线上。大角度90°输出推算测试的峰值电流约0.605 A。

## 网页与复现

1. `python tools/launch_dashboard.py`，打开 `http://127.0.0.1:8766/?focus=COM23&v=commissioned-20260905`。新电脑使用实时端口，网页不要套用旧COM号。
2. 确认36GP档案、母线、nFAULT和“已载入校准”。首次先用短电流/速度诊断，位置目标均是**后轴**，滑块范围可以收窄，选择范围不会运动。
3. 原始遥测100 Hz；网页按显示器原生帧率绘制，每一帧可含多个真实样本，不插值造数据。当前单板只读测试约56 fps，无页面异常、横向溢出或误发运动。
4. 双板同步/力反馈收在折叠区，当前只有一块板，不能验收双向负载效果。
5. 界面已按工具中心登记技能加入本机统一工具中心，独立入口仍为8766。

最终停止状态检查：12轮 `sleep → wake → stop → status`，共51个ACK全部收到，平均28.49 ms、最大103.91 ms（包含唤醒时校零等待）；每轮均检查 `pwm=0/4095`、`control=idle`、`nFAULT=1`。这不是24小时稳定性认证。证据：[回执记录](../evidence/commissioning/20260905-105935-link-ack.json)。最终只读UI复测为100.0 Hz／57 fps，无脚本错误，也没有任何运动/参数写入。
