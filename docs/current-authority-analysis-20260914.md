# 转动时电流失跟：已有数据审查与集中修正

本轮未发出任何运动命令。仅读取旧文件、下载后台已有日志、进行离线测试与静止部署。用户要求减少实际转动，不以轮番扫参数替代分析。

## 证据分级

1. **已证实的覆盖缺口**：`basic-current-1788922014858.json` 中两板短脉冲的最高输出转速分别仅 0.1118 / 0.1309 r/s。过去低速、滤波后电流通过，不证明高速电流稳定，更不是 PWM 纹波验收。
2. **已证实的结构性限制**：原电流/旋钮/力反馈模式以 `Ke*omega ± R*I_limit` 限制 PI 输出电压，位置/速度模式却允许 PI 使用实际 PWM 电压范围。模型偏差大时，电流误差积分无法突破模型限制，产生持续失跟；这与没有反馈是不同问题。
3. **模型偏差线索，不是当前模型验收**：当前 R=2、Ke=0.011；历史低速拟合 R约3.26–3.41、Ke约0.0257–0.0263，部分方向未通过。不能直接把旧值写入板子，更不能外推后冒充现时实测。
4. **解析反例**：若实际 Ke=0.026、R=3.3，输出8 r/s时保持0.15 A约需7.291 V；旧模型上限仅5.275 V，虽然电源有19.5 V仍会被软件卡住。该数值证明旧逻辑有可能阻止可实现的电流目标，不是对当前硬件所需电压的测量。
5. **前馈噪声通道**：速度估计直接乘Ke变成电压，因此编码器求导波动也进入PWM。对旧100 Hz长行程记录做10 ms前馈平滑回放，在选定稳定参考区间，电压步进RMS：COM4 0.320→0.221 V，COM23 1.077→0.654 V。仅代表记录中的前馈变化减少，不等于实机电流纹波下降，也不能覆盖50 Hz以上内容。

可复现：`node tools/analyze_current_authority.cjs`。已有后台缓冲抓取：`evidence/current-existing-buffer-1789371118348.json`，只包含静止数据，未据此编造高速失跟比例。

## 本轮修正

- 模型保留为前馈，但不再以未经验证的 R/Ke 包络硬截 PI 输出。所有模式均使用实际 PWM/额定电压范围，电流误差仍由实测电流闭环纠正。
- 只对反电动势前馈的速度增加10 ms时间常数；不改位置/速度反馈，不加重现有1.522 ms电流反馈滤波。18,000电机轴deg/s²匀加速下，由该前馈延迟引入的模型电压差解析测试小于0.04 V（Ke=.011）。
- 保留80%目标电流限幅、实测电流保护、供电/nFAULT检查、真实PWM/额定电压上限和积分抗饱和。此次修改确实影响电流/力反馈内环的电压权限；不能沿用旧力反馈验收直接宣称新内环已验收。
- RAM `T` trace 前8列兼容旧格式，追加：四次ADC均值换算电流（数字低通前）、实际电流周期us、前馈EMF电压、PI请求PWM、实际PWM、标志。标志bit0滑行、bit1旧型号互锁、bit2电压饱和、bit3积分dt被限。数据仍在停机后转储，不向USB实时倾倒2 kHz记录。
