同一套 ESP32-S3 固件驱动两块相同电路板，提供：

- 目标 2 kHz 电流环、500 Hz 速度环、200 Hz 位置环；实际频率/间隔须用过程记录核验；
- MT6701 多圈位置、INA240A1 电机支路电流和母线电压遥测；
- 1 Mbaud、8N1、CRC16 的地址化单线 DATA 总线；
- 双板位置同步与双向虚拟弹簧/阻尼力反馈框架；
- 实时 USB 网页调试台和 CSV 原始过程导出。

## 统一固件原则

两块板使用 `firmware/` 的同一实现，不按 COM、USB 序列号或 MAC 分叉。电机档案选择默认值，每台装配可保存自己的方向、采样极性、R/Ke、机械模型、转角扰动补偿和 DATA 地址。多圈零点是本次上电的相对原点。更换电机、磁铁安装角或接线需要重新校准，不能把某台的补偿表复制成通用常数。默认运行环境为 TinyUSB CDC；构建平台固定在已测试的 Espressif32 6.4.0 / Arduino 2.0.11。

## 安全状态

上电和复位默认 `nSLEEP=0`、PWM=0；不得自动恢复旧目标。确认驱动 VM、nFAULT、编码器和电流零点后才动作。36GP-555 外环默认上限为 **0.6 A**，电机档案软件包络为 2 A；均不是连续额定电流认证。原 775 的约 5 A 板级限流/7 A 诊断设置不得套用到新电机。保留电源限流和外部急停；1秒任务看门狗仅是软件失联后备，不是硬件急停。6 V 电机档案与驱动 VM 的区别见 [hardware.md](docs/hardware.md)。

## 36GP-555 新电机档案

网页的“电机档案”选择 `36GP-555` 后，固件使用 24 V、1538 rpm、1:5.2 的参数档案。MT6701 在电机后轴，内部原有三环仍采用原坐标和已调好的参数；**网页位置、速度、目标、曲线及 CSV 全部采用输出轴坐标（后轴 ÷ 5.2）**。输出轴 1 圈对应后轴 5.2 圈。速度环增益显示时乘减速比，下发时除回；位置 Kp/Ki/Kd 不变，速度限幅和角度死区按减速比换算，避免改变控制器。输出轴为推算值，不包含齿隙或扭转形变的独立测量。

## 单电机力反馈旋钮（新固件，待通电验证）

- 顶部卡片提供连续卡点、弹性回中、纯阻尼、卡点加两端软限位；不依赖双板 DATA 总线。
- 卡点间距 2–90°（输出轴），默认 15° / 每圈 24 个；网页强度默认 500 mA，需显式启用。力臂默认 25 mm，显示模型估算杆端力，非实测手力；阻尼与范围均为滑块。
- 按“启用旋钮”才启动，以当时输出轴位置为中心；配置、刷新、连接均不自动起力。
- 板端 500 Hz 力曲线直接生成电流目标，保留原 2 kHz 电流 PI；不加旧电机 2 A 脱困下限。
- 旋钮总电流限幅 0.6 A、通信租约 1 s、单次硬上限 60 s。失联/超速/采样异常/STOP 后必须重新手动启用；60 s 仅是调试限制，不是连续温升认证。
- 目标滑块由“停止拖动后发送”改为最多 40 次/s 的最新值限频发送；只有一个在途事务，不积压旧目标。

商品信息没有给出堵转电流或连续绕组电流，`2.0 A` 是新档案的初始调试电流包络，不是电机额定堵转电流。正式提高电流前，应在当前母线、电机温升和 INA240 实测数据基础上重新辨识；不能用 `15 W / 24 V` 的空载功率反推堵转电流。

## 换电脑直接运行

Windows 11 安装 Git、Python 3 和 PowerShell 7 后，在 PowerShell 7 执行：

```powershell
git clone https://github.com/cdh66666/dual-esp32-motor-force-feedback.git
cd dual-esp32-motor-force-feedback
python .\tools\launch_dashboard.py
```

脚本会安装 `pyserial`、启动本机网页服务并打开 `http://127.0.0.1:8766/`。网页实时枚举当前电脑的 ESP32 USB 串口，不依赖 COM18/COM19 这些历史端口号。给另一台电脑上的 Codex 仓库链接和一句“按 README 启动调试台”即可复现界面；实际控制前仍须确认新电脑识别到板卡并且板上固件版本一致。

## 编译与烧录

```powershell
python -m pip install platformio
cd firmware
pio run
pio run -t upload --upload-port COMx

cd ..\web
python -m pip install -r ..\requirements.txt
python server.py
```

浏览器打开 `http://127.0.0.1:8766/`。固件烧录前必须重新枚举 USB 身份，不能只相信历史 COM 号。

对已经响应的 TinyUSB 应用，可用身份校验脚本完成 STOP、休眠、进入 ROM、烧录和重新枚举；不擦除 NVS，不请求电机运动：

```powershell
python -m pip install -r requirements-commissioning.txt
# 以下为本次板卡；其他设备必须改为它自己的实时端口与序列号。
python tools/reflash_board.py --port COM23 --serial 68EE8F52A79C
python tools/reflash_board.py --port COM23 --serial 68EE8F52A79C --flash
```

如果端口或串号不匹配、STOP 无回执，脚本拒绝操作。COM 枚举早于固件初始化完成，所以脚本会等待真正回执；它不能修复损坏的 USB 硬件。

## 限时诊断与复位

- 电流目标每次拖动默认只保持 1.0 秒，范围 0.1–10 秒，到时由固件停止；
- 速度目标每次拖动默认只保持 3.0 秒，范围 0.1–30 秒，到时由固件停止；
- 电流和速度诊断不自动续租，位置保持仍按安全看门狗续租；
- `全部 STOP` 会停止并重新准备驱动；旁边的 `复位全部` 会对所有在线板执行 STOP、功率通路恢复和状态读取，不会恢复旧目标；
- 显示单位默认使用圈和 rps，可切换为角度和 °/s。
