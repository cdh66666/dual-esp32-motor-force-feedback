# 停机状态与采集利用修正

本次证据：`20260908-170454-910403800-COM4.jsonl` 与 `20260908-170456-526926800-COM23.jsonl`。

COM4 停机前最后一条 CASCADE 速度为电机轴 1668.3°/s（输出约 320.8°/s），母线约 19.65 V、电流约 0.22 A；随后触发旧版合并的 force_envelope。超速是合理怀疑，但旧固件未记录触发项，不能事后证明唯一原因。

关键代码缺陷：motorStop 使 syncMotionArmed=false，却不强制 driverAwake=false；已停止节点仍处理并回复总线帧，而 payload.awake 仅依据硬件驱动是否唤醒。另一端可能继续收到 fresh/awake/healthy 的停止节点状态，因此不会及时停力。0.5.7 改为 driverAwake && syncMotionArmed，保留消息回复但明确报告不可运动。

0.5.7 同时输出保护具体原因、输出轴速度、速度限值、启动/当前母线、电流及电流限值、会话时长。未放宽原保护边界。前端收到 force_envelope 时停止另一端并持久显示具体原因，不以通用停止成功覆盖。

反向电流尖峰尚未定因。提供的三张截图没有实际电流波形；历史 100 Hz 遥测不能分清电流环制动瞬态、桥路衰减路径与采样混叠。STOP 当前是 ENBL PWM=0，并非闭环渐减电流；未在未核对芯片完整真值表时擅自改变 nSLEEP 或 DECAY 行为。需升级后的高速波形比较，不能宣称尖峰已消除。

页面采用可拖动非模态设置窗，全部 STOP 仍可访问；打开时从一致的两板回读值填充。加入已有采集分析按钮（无运动指令），新采集完成自动作 R/Ke/电压偏置初拟合、留出误差诊断。旧记录缺少减速比时明确标为按输入框的诊断假设。仍因缺少电感、延迟和机械模型验证而不自动写入三环增益；没有把初拟合冒充自动整定。

本轮编译、启停回归、示波器回归、初拟合合成数据测试通过，实际页面悬浮窗开闭检查无 JS 错误。固件尚未烧录；检查时两板母线约 19.6 V，保持现有烧录入口的母线 <1 V 条件。
