# Device ID setup and persistent desktop discovery

Implemented desktop bus-window ID read/save. Saving requires both configured boards connected by USB, exact UID and session, a unique integer ID 1–254, STOP/sync-off/sleep acknowledgement and stopped telemetry on both boards. An ownership guard prevents other threads from sending non-stop/configuration traffic during the transaction. Changes are read back before success; unchanged IDs avoid NVS writes. Existing firmware busaddr command is used. Motor tuning unchanged; no motion commands.

DeviceTopology stores UID/address mapping in web/device_ids.local.json (gitignored), using atomic replacement and unchanged-data write suppression. Discovery updates recognized UID observations. USB remote routing reads this map, removes old-address routes and requires fresh telemetry at the new address. The map remains for the two known hardware identities, not arbitrary-size enrollment.

Phone-specific code was not modified or flashed. Native hotspot local address updates only on the next board restart. This limitation is displayed before saving an ID.

Verification: seven Python ID tests passed (persist, collision, wrong UID, two-board requirement, invalid values, mismatched readback, unchanged ID); panel mock ID binding and transport remapping tests passed. Phone ownership regression passed. All changed desktop assets served exactly from disk. Project backend was stopped after confirmed STOP/sleep and restarted on port 8766.

Live acceptance blocked before any ID write: COM4 recovered; COM23 enumerates with PnP status OK but USB opening/recovery repeatedly returns Windows error 31. COM23 still responds to DATA via COM4 with UID 9CA7528FEE68, ID 1, idle PWM 0 / awake 0, VM 19.55 V. This is USB-path evidence, not proof of a dead board. User asked to tap COM23 RST. No actual IDs have been changed in this turn; real temporary-ID / DATA lookup / restore test remains pending.

Scope remaining: editing an ID through a DATA-only connection, phone dynamic-address parity, remote advanced controls and performance acceptance are not completed by this feature.
