# 单 USB / 板端热点网关进度

用户要求：任意一板 USB 接入可以控制 DATA 链设备；板端提供热点和独立手机网页。
暂停控制抖动优化；网络开发不触发运动。

## 当前实现边界

现有程序没有 Wi-Fi 服务，也没有整链设备发现/虚拟设备会话。
现有 DATA 帧负载上限 96 字节，不能直接透传完整配置回读；需分片或结构化协议。
当前网页按串口建会话，不能把只有本地 USB 回执的 `bus_tx` 当作远端执行成功。

## 本次先修的真实缺陷（待部署）

- 远端命令返回 ERR 后仍发 executed ACK：改为观察实际处理结果，失败 NACK；ACK仅代表接受，不代表运动完成。
- 新事务覆盖未结束事务：返回 busy，不覆盖等待记录。
- 广播 STOP 后旧事务仍可能重试：取消待重试命令，避免恢复旧目标。

## 后续不可跳过的交付

1. 地址/UID 发现，重复地址诊断，命令序号与重试去重，配置分片回读。
2. 电脑后台逻辑设备与物理 USB 分离：本地和远端统一路由，掉线清除目标，远端超时不伪装在线。
3. 板端 AP + 页面 + 有界命令队列；Wi-Fi/HTTP 不能在控制线程阻塞，不允许多客户端抢占控制。
4. 两端分别作为网关，先无运动验证全套回读和拒绝，再验证实际断开其中一条 USB；软件模拟不能冒充单线验收。
5. 手机连接板端 SSID、网页访问和控制实测；电脑局域网网页不算板端热点完成。

尚未完成上述功能，不应公布不存在的热点或声称任意 USB 全链路已经可用。
