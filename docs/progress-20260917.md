# 双板总线力反馈项目进度 · 2026-09-17

## 结论

项目已经是可编译、可离线回归、可进行双板总线调试的工程原型，当前主线仍是“实机调试收尾”，不是可直接宣称长期稳定的成品。

核心 8 项按等权计算，当前综合进度约 **70/100**。这里的分数表示距离“当前版本完成真实验收”的可信完成度：代码契约测试可以证明接口和边界，但不能替代电机运动、带载电流、温升、无线连接或人的实际手感。历史 `0.5.9-sync-trace` 的力反馈通过记录只作为基线，不能自动覆盖当前 `0.5.10-single-usb-force` 候选。

## 当前代码分层

- `firmware/include/`：可独立测试的控制数学、交互保护、USB 输出策略、DATA 命令缓存/回执、网关命令白名单和链路指示。
- `firmware/src/main.cpp`：板端控制状态机、三环调度、编码器/电流采样、DATA 协议和串口命令；`wifi_gateway.cpp` 只负责 AP/HTTP/有界队列，不在 Wi-Fi 任务里直接驱动 GPIO。
- `web/server.py`：串口会话、维护/手机交接、DATA 网关 API 和 UID/会话校验。
- `web/*-transport.js`：桌面直连、单 USB DATA 对端、板端热点三种传输分别实现；远端动作通过新鲜遥测、会话和租约检查。
- `tools/`：烧录/恢复和实机测试入口；`tests/`：离线契约和模拟 I/O；`docs/`、`evidence/`：证据与历史边界。

## 与上一版 `007032d` 相比的主要优化

1. 固件从 `0.5.9-sync-trace` 推进到 `0.5.10-single-usb-force`：低速速度估计改为 5 ms 窗口并在低速混合增量中值；零电流噪声区清积分并滑行；位置参考加入板端限加速度/限 jerk 轨迹；电流 trace 记录原始电流、前馈、请求/实际 PWM 等字段。
2. 单 USB DATA 从只读查询扩展为主页面远端卡片、位置/速度/电流/PWM 路由、明确的 ACK/NACK、UID/协议/会话校验和过期 STOP；位置目标增加 500 ms 租约续期，PWM 不盲目续期。
3. 修复网关重复事务和停止后唤醒状态误判：板端对同源/同序号/同命令做 300 ms 有界去重，主机 META/唤醒状态按会话和 STOP 纪元缓存；不再用本机 `bus_tx` 回执冒充远端执行成功。
4. 增加板端 Wi-Fi AP、DHCP 状态和通信 LED、同源桌面/手机页面、手机/电脑串口交接以及失效请求拒绝；Wi-Fi 通过有界队列进入控制循环。
5. 烧录工具锁定 PlatformIO 4.5.1 esptool、同时写入两个 OTA app 槽并保留身份/停止/电压前置检查；增加 USB 恢复、拓扑、网关、租约、手机页、静态资源和单 USB 运动质量测试。
6. 发布说明不再把显示滤波、离线模拟或网页回执称作物理通过，并把失败记录、未部署候选和当前实机边界保留在日期文档中。

## 下一步按优先级

1. 保持两板停止、无外力，松开 BOOT 后分别按 RST；只做 `MODEL/STATUS/WIFI/双向 DATA` 应用态回读，不恢复旧目标。
2. 对当前候选先逐板做小角度、低速、正反向位置和电流 trace，确认新固件实际运行；完成后 STOP/sleep 并保存原始证据。
3. 仅在低速结果稳定后，再做有界 15 r/s 参考测试、全范围换向、带载电流和温升；记录母线、电机支路电流、nFAULT、位置误差和回灌风险。
4. 补做 COM4-only / COM23-only 两个单 USB 入口的真实远端运动，再做双向力反馈持续与断链停机；手机无线放在这之后。
